# 选项动作编辑器设计

`decision-actions-redesign.md` 的前端部分，对接编辑协议版本 7（落盘为 `{"version":5}`）。验收与后端一致：管理员删光默认题后，只靠“新建普通题、选触发来源、给选项绑动作”，重建群聊回复、冷场发言、指定消息引用和正文后配图。

## 原则

1. **每道题读成一句话。** 何时提问 → 问判断模型什么 → 每个选项选中后做什么、接着问谁。卡片按这个顺序分区。
2. **没有专属用途。** 页面不再出现 `role`、固定选项 ID 的用途说明、“且允许发言”和 `setGateEvent`。发言、引用、配图都是选项上的动作芯片，选项 ID 由管理员命名。
3. **能做什么由目录决定。** 添加动作菜单、参数控件、可用阶段都从 GET 返回的 `actions` 生成。不可用的动作留在菜单里置灰并写明缺什么，不隐藏。
4. **结构修改不留悬空引用。** 删除题或选项、切换候选来源、题型或阶段时，前端立即移除指向失效对象的触发来源和动作。会移除内容时，按钮先进入“再次点击确认”并写明数量。撤销更改可以找回。
5. **配置顺序有语义。** 多个引用同时命中取最后一个，交给会话模型的材料按题目顺序拼接。卡片列表保持配置顺序、可排序；流程图只用于导航和检查。

## 页面结构

“判断配置”页自上而下：

## 流程泳道

```
┌ 收到消息 ─────────────── 2 道入口 · 请求发言：join=接话 ┐
│ 1 join      选择题   接话 💬 → 2 · 略过                  │
│   └ 接话 · 同批 → 2 specific   要 → 3 · 随聊             │
│        └ 要 · 同批 → 3 which   每条消息 📝❝ · 不针对      │
│ 4 asking    是否题   只记录答案                           │
├ 达到冷场时长 ──────────── 1 道入口 · 请求发言：idle=是 ┤
│ 5 idle      是否题   是 💬                               │
├ 本轮正文生成完成 ────────────────────────────────┤
│ 6 fits      是否题   是 → 7                              │
│   └ 是 · 同批 → 7 pick         每张表情 🖼正文发送后        │
├ 待连接 · 不会被提问 ─────────────────────────────┤
│ 8 orphan    选择题   [选择触发来源]                       │
└──────────────────────────────────────────────┘
```

- 泳道按 `events` 的顺序排，最后一条“待连接”由前端分组，收 `triggers: []` 的题和迁移留下的孤立题。
- 直接订阅事件的题是入口。子题挂在触发它的选项下，边上写“选项 · 同批”或“选项 · 命中后问”。多来源的题第二次出现时显示“（同上）”，不再展开。
- 节点只列有动作或有后继的选项。图标：💬 发言，📝 交给会话模型，❝ 引用，🖼 表情。全部选项无动作、无后继时写“只记录答案”。
- 泳道头列入口数和全部 `request_reply` 来源，说明多处请求只生成一次正文。是否题的来源显示为“是”“否”，不显示 `true`、`false`。“收到消息”或“冷场”泳道里没有可达的发言动作时，加一行说明：“这个事件不会调用会话模型发言，独立动作照常执行。”这是说明，不算错误。
- 没有入口的泳道显示“没有题订阅 · ＋添加入口题”。按钮新建一道订阅该事件的空白是否题并展开。“本轮正文生成完成”泳道新建的题自动设为正文生成后。
- 停用题半透明。互相触发成环、没有入口的题单独列一组红色提示（沿用现状）。点击节点跳到卡片并展开（沿用）。试算后节点显示状态徽标。

## 问题卡片

### 折叠态

标题行依次是序号、ID、题型，以及候选来源（仅动态来源）、“正文后”、单题决策模式、“待连接”（琥珀色）、“待完善”（有校验问题）、改动标记。右侧控件沿用现状：启用开关、复制、上移、下移、删除。

摘要两行：第一行是题干；第二行是触发描述，加上每个选项的芯片（选项名、动作图标、→ 子题）。

#### 何时提问

- **阶段**：正文生成前 / 正文生成后，对应 `stage`。阶段决定下面可选的事件、上游和动作。
- **触发来源**：每行一个下拉框，分“事件”和“上游选项”两组。
  - 正文生成前可选“收到消息”“达到冷场时长”，以及其他正文前题的选项。
  - 正文生成后可选“本轮正文生成完成”，以及任意题的选项。
  - 本题自身、本题其他行已用的来源不出现。选了会成环的上游置灰，提示“会形成循环”。
- **提问时机**：只有上游来源才有，新建时默认“随上游同批”。上游在正文前、本题在正文后时固定为“命中后再问”，旁注“需等正文生成”。本题按权重随机时不显示这一项，旁注“本地随机，无需等批”。只要有一行选了同批，下方就提示：“同批只是提前问，上游命中后才采用答案。”
- **没有来源**：显示琥珀色提示“待连接：这道题不会被提问”和“＋添加触发来源”。可以保存。
- **限定条件**：场景为四个可多选的标签，对应 `scenes`，不选即不限；“有候选时才问”对应 `requires_candidates`。旁边按事件与场景的交集算出一句“实际会在：……时问”，并注明场景限制对上游来源同样生效。

#### 问判断模型

- 题目 ID 就是题名，判断请求和日志都用它。选项 ID 也由管理员命名，可以用中文。
- **候选来源**对应 `candidate_source`，与触发来源分开。下拉可选“固定选项”“最近用户消息”“图库分类”“全部图库图片”或“其他问题选中项的下级候选”。动态来源锁为选择题并追加 `*` 行，说明默认 `{描述}`。最后一种还需选择能提供下级候选的“来源问题”，保存为 `{"question":"来源题ID"}`；默认 `meme_id` 引用 `meme_category`。摘要显示引用并可跳转到来源，提问时机固定等待来源答案。重命名同步引用；删除或停用来源后标记错误，必须修复或停用依赖题才能保存，不能自动改成全库。
- **预览候选**随来源的示例答案变化，例如分类选择“开心”，图片示例中只出现该分类的图片。试算结果列出各批次的实际候选和跳过原因，不会把其他分类的图片混入当前批次。
- 题干输入框保留 `{当前时间}`、`{冷场时长}` 插入按钮。动态来源加一行说明：“候选行会展开为本轮快照中的每条消息（最多 8 条），`{描述}` 换成发送人、时间和摘要”；图库分类写“每个带描述表情所属的分类”，图库表情写“每张带描述的表情”。

#### 选项与结果

列为“选项 · 判断模型看到 | 权重 | → | 选中后”。是否题固定“是”“否”两行。选择题至少两项，可增删、排序。`*` 行只在动态来源下出现，不能删、不能改 ID；固定选项来源的选项 ID 不能填 `*`。按权重随机时显示抽中比例，`*` 会展开成多个候选，所以有 `*` 的题不显示比例。

“选中后”格包含：

1. **动作芯片**，从上到下即执行和拼接顺序。每个芯片带内联参数，`⋯` 菜单提供上移、下移、移到其他选项、删除。“移到其他选项”用来完成“把发言从‘是’移到‘否’”这类改动，只列移过去后仍然合法的选项，例如取本题消息的引用只能留在 `*` 行。
2. 没有动作时显示灰字“无动作，只记录答案”。
3. **＋添加动作**：菜单由 `actions` 目录生成，见下表。
4. **接着问**：已有子题以按钮列出（点击跳转），后附时机。下拉框可选现有题，或新建空白是否题、选一条消息、选一张表情。新建的题插在本题之后，触发来源预填为“本题选此项 · 同批”。

| 动作 | 参数控件 | 旁注 | 置灰原因 |
| --- | --- | --- | --- |
| 💬 调用会话模型发言 `request_reply` | 无 | 全局有多个来源时写“与 idle=是 等 N 处共用一次生成” | 正文生成后：“正文已生成”；本选项已添加 |
| 📝 将内容交给会话模型 `add_context` | 内容：本题答案（省略 `from`）/「某题」的答案（`from`）/ 固定文本（`text`）；字段名（`label`，可选） | 本题答案在消息题 `*` 行写“发送人、发送时间和完整原文”，在表情题写“表情描述”，在固定选项写“答案「接话」”；字段名写“会话模型会看到「篇幅：简短」” | 正文生成后 |
| ❝ 引用选中的消息 `quote_message` | 消息：本题选中的消息 /「某题」选中的消息 | “引用方式沿用群聊策略的「指定消息的引用方式」”；全局有多个引用时写“同时命中时采用排在最后的「某题」” | 正文生成后；没有候选为最近用户消息的题；本题是消息题但当前行不是 `*` 且没有其他消息题 |
| 🖼 发送表情包 `send_meme` | 表情：本题选中的表情 /「某题」选中的表情；时机：判断后立即发送（`on_match`）/ 正文发送后配图（`after_send`） | `on_match` 写“不等正文，本轮不发言也会发”；`after_send` 写“正文确认发送后再发，本轮不发言就跳过” | 没有候选为图库表情的题；本题是表情题但当前行不是 `*` 且没有其他表情题 |

“某题”下拉按配置顺序列出符合条件的题：引用和表情只列对应来源的题；正文前的动作不列正文后的题。选中的题不是本题上游时提示：“「某题」未提问或未命中时跳过这个动作。”

#### 判断方式与兜底（折叠）

| 控件 | 字段 | 说明文字 |
| --- | --- | --- |
| 本题决策 | `decision_mode` | 继承默认 / 模型判断 / 按权重随机 |
| 使用插件判断阈值 | `use_threshold` | 沿用现有说明 |
| 没有有效答案时记为 | `default_option` | “只写进日志，不执行该选项的动作，也不触发接着问。”不列 `*` |
| 私聊收到消息时直接采用 | `private_default` | “不问判断模型，按选中该项执行动作并触发接着问。”只在本题会在私聊收到消息时提问才显示 |
| 判断模型可能输出的别名 | `aliases` | 别名 → 选项的键值列表。仅在已有别名时显示，新建题不提供入口 |

## 前端数据模型

编辑期间全部用对象引用，保存时再序列化成 ID，这样改题名、改选项名、排序都不会断引用。现有 `triggers` 已经这样做，这次扩展到动作和默认值。

```js
question = {
  id, enabled, type, instructions, use_threshold,
  decision_mode: "inherit" | "model" | "random",
  stage: "pre_reply" | "post_reply",
  candidate_source, requires_candidates, scenes: [],
  options: [{ id, criteria, weight, actions: [Action] }],     // 选择题
  sides:   { true: { weight, actions }, false: { weight, actions } }, // 是否题
  triggers: [{ event } | { parent: Question, option: Option | "true" | "false", ask_with_parent }],
  default_option: Option | "true" | "false" | null,
  private_default: 同上,
  aliases: [{ alias, option: Option }],
}
Action = { tool, from: Question | null, text?, label?, when? }
```

- 读：`GET decision-config?version=7`，在 `normalizeQuestion` 里把 `actions[key]` 挂到对应选项上，`from` 解析为对象。
- 写：`POST decision-config`，提交 `{version: 7, decision_mode, decision_custom_context, decision_questions}`。空动作数组不输出，`from: null` 省略。读入时也按此规则整理一次，避免基线无谓地显示“已修改”。
- 预览：`POST decision-preview`，带 `version: 7`。
- 把 normalize、serialize、validate、级联清理、动作可用性和泳道计算抽成无 DOM 的 `views/meme_manager/workflow-model.mjs`，用 `node --test` 测试（参照 `tests/log-probabilities.test.mjs`）。`app.js` 只负责渲染。

## 校验

前端与 `config_util._validate_triggers` 和 `workflow_actions.validate_actions` 保持一致，并且能定位到字段。后端只返回一句话，所以保存前必须由前端先拦下。

| 规则 | 标记位置 |
| --- | --- |
| 题目 ID、选项 ID 非空且不重复；说明非空；权重 0–100，至少一项大于 0；选择题至少两项 | 对应输入框 |
| 动态来源需要选择题和 `*` 行；固定来源不能有 `*`（前端额外规则，后端未拦） | 候选来源 |
| 事件与阶段匹配；事件行不能同批；上游选项存在；正文后的题不能触发正文前的题；跨阶段不能同批；来源不重复；不成环 | 对应触发行 |
| 动作阶段在目录 `stages` 内；参数在 `parameters` 内且非空；`text` 与 `from` 二选一；`from` 存在且阶段可用；带 `source` 的动作，来源题的候选类型一致，取本题时只能在 `*` 行 | 对应动作芯片 |
| `when` 在目录列出的值内 | 时机控件 |
| 场景合法；`default_option`、`private_default` 是本题选项，动态来源不能选 `*`；别名不与选项重名，并指向现有选项 | 折叠区（自动展开） |

“待连接”不算错误。卡片和泳道显示琥珀色，保存栏写“N 道题待连接，保存后不会被提问”。

## 级联清理

| 操作 | 前端立即处理 | 先确认 |
| --- | --- | --- |
| 删除题 | 移除子题中指向它的触发来源，没有其他来源的子题进入待连接，不会自动变成入口；移除其他题中 `from` 指向它的动作 | 有引用时确认，写明“N 条触发来源、M 个动作” |
| 删除选项 | 移除该选项的动作、子题指向它的触发来源、指向它的默认值和别名 | 有绑定时确认 |
| 动态来源改为固定选项 | 删除 `*` 行及其动作和子题触发；移除其他题中引用本题的引用、表情动作 | 有内容会被移除时确认 |
| 固定选项改为动态来源 | 改为选择题，追加 `*` 行 | 否 |
| 是否题改为选择题 | 无损转换为“是”“否”两个选项，权重、动作、子题触发、默认值随之迁移 | 否 |
| 选择题改为是否题 | 移除全部选项上的动作、子题触发和默认值 | 有内容会被移除时确认 |
| 正文前改为正文后 | 把“收到消息”“冷场”换成“本轮正文生成完成”并去重；上游行改为“命中后再问”；移除只能在正文前执行的动作；移除正文前的题里 `from` 指向本题的动作，以及由本题触发的正文前子题的触发来源 | 有内容会被移除时确认 |
| 正文后改为正文前 | 移除“本轮正文生成完成”和正文后的上游来源 | 有内容会被移除时确认 |
| 改题目 ID 或选项 ID | 对象引用，无需处理 | 否 |

保存时后端也会剥掉已删父题的触发来源。前端提前处理，用户就能先在泳道里看到结果。

## 新建与模板

“添加问题”菜单，以及“接着问”下拉里的新建项，都生成普通题，生成后可以任意修改：

| 模板 | 生成内容 |
| --- | --- |
| 空白是否题 / 空白选择题 | 无动作。从底部菜单新建时为待连接，焦点放在触发来源 |
| 选一条消息 | 选择题，候选与“有候选时才问”都设为最近用户消息；选项为 `*`（`{描述}`）和“不针对”；`*` 绑定“交给会话模型”和“引用”；没有有效答案时记为“不针对” |
| 选一张表情 | 选择题，候选为图库表情；选项为 `*` 和“不配图”；`*` 绑定“发送表情包 · 正文发送后”；没有有效答案时记为“不配图” |
| 正文后检查 | 是否题，正文生成后，订阅“本轮正文生成完成” |

泳道上的“＋添加入口题”生成订阅该泳道事件的空白是否题。“恢复默认问题”使用 v7 投影后的 `default_questions`。

空配置时问题区显示：“还没有题目。没有题目订阅事件时插件不发起判断，也不会调用会话模型发言。”下方给出两个按钮：“添加入口题”和“恢复默认问题”。

## 用界面从空配置重建

后端文档里 A–E 五道题的搭建步骤：

1. “收到消息”泳道 → ＋添加入口题 → 改为选择题，题名 `join`（A），选项“接话”“略过”。“接话” → ＋添加动作 → 调用会话模型发言。
2. “接话”行 → 接着问 → 新建空白选择题 `specific`（B），触发来源已预填“join 选接话 · 同批”。选项“要”“随聊”，不绑动作。
3. `specific` 的“要”行 → 接着问 → 选一条消息，得到 `which`（C）。`*` 已带“交给会话模型”和“引用”。
4. “收到消息”泳道 → ＋添加入口题 → `asking`（D），不绑动作。
5. “本轮正文生成完成”泳道 → ＋添加入口题 → `fits`（E）。“是”行 → 接着问 → 选一张表情，得到 `pick`。
6. “达到冷场时长”泳道 → ＋添加入口题 → `idle`，插入 `{冷场时长}`，“是”绑定调用会话模型发言。

试算“群聊收到消息”，假设 join=接话、specific=随聊：正文前 1 次判断请求，丢弃 `which`；正文后另有 1 次；发言来源 `join=接话`。再改为 join=略过：只剩正文前 1 次请求，丢弃 `specific`、`which`，保留 `asking`，不发言，正文后不计算。

## 试算一轮

```
试算一轮   场景 [群聊收到消息 ▾]   [运行]        配置已更改，结果已过期
假设答案（不调用判断模型）
  join [接话 ▾]  specific [随聊 ▾]  which [示例消息 ▾]  asking [否 ▾]
  fits [是 ▾]    pick [示例表情 ▾]
───────────────────────────────────────────────
判断请求    2 次
  第 1 批 · 正文前   问 join、specific、which、asking   丢弃 which
  第 2 批 · 正文后   问 fits、pick
会话模型    生成 1 次   来源 join=接话
  交给会话模型   无
引用        无
动作        🖼 send_meme · 正文发送后 · 计划中 · 来源 pick=sample_meme
```

- 场景为群聊收到消息、私聊收到消息、群聊冷场、私聊冷场四种。假设答案只列在该场景下可达的启用题，默认取第一个权重大于 0 的选项。`*` 显示为“示例消息”或“示例表情”。
- 返回字段的展示方式：

| 字段 | 展示 |
| --- | --- |
| `batches[].asked/used/discarded/stage` | 请求次数，每批的阶段、问了哪些、采用了哪些；丢弃项用删除线 |
| `answers` | 有效答案 |
| `reply`、`reply_sources` | “生成 1 次 · 来源 …”或“不发言” |
| `context.message/fields/answers/hints` | 选中的消息、命名字段、普通答案、固定文本 |
| `quote` | 引用的消息 ID |
| `tools[]` | 名称、时机、参数、来源、`status` 和 `reason` |

- 泳道节点同时加徽标：采用、丢弃、未提问。“未提问”由前端用全部题减去 `asked` 算出。
- 试算后再编辑任何内容，结果就标为过期，不自动重算，免得每次按键都发请求。
- 正文后的题只在正文前请求了发言时才计算，结果里写明这一点。

## 迁移和旧编辑器

- GET 返回的 `warning` 显示在问题区顶部横幅。孤立题出现在“待连接”泳道。
- 存储仍是 v4 时，首次保存会把配置升级。保存栏需要提示：“保存后配置升级为选项动作格式，旧版编辑页将无法再保存。”POST 返回 409 时，横幅写“配置已被新版编辑器升级，请刷新”。

## 需要后端补的契约

| 缺口 | 影响 | 建议 |
| --- | --- | --- |
| v7 投影总是返回 `workflow_version: 5` | 前端无法判断这次保存是不是首次升级 | 已补：GET 另返回 `stored_version`（落盘图版本，未保存过时为 `null`） |
| 迁移提示是一整句拼接文本 | 无法挂到对应卡片 | 加 `migration_notes: [{question, message}]` |
| `actions` 只给参数名和 `when` 的取值 | 参数标签、时机文案只能写死在前端 | 加 `parameter_labels`、`when_labels`、`description`；前端先内置映射，没有映射时显示原键名 |
| 场景列表不在返回值里 | 前端要硬编码四个场景 | 加 `scenes` |
| `default_option` 的兜底答案不执行动作，`private_default` 会执行 | 两个字段的界面文案差异很大 | 请确认这是预期行为。本文按现有实现写 |
