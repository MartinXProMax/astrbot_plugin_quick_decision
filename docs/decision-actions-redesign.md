# 从空配置重建发言流程

版本 5 判断配置的设计和后端接口。旧实现的对照基线为 `e800ef8`。验收从一份空的判断配置开始。管理员新建普通题、选择触发条件、给选项绑定动作，就能重建默认群聊回复、冷场发言和指定消息引用。题目和选项都允许自行命名。

## 当前实现在哪一步失去可配置性

| 环节 | 当前行为 | 直接后果 |
| --- | --- | --- |
| 事件与前判断 | `_build_specs` 只把当前事件对应的 `role=action` 题置为入口。其他题填写事件时，引擎替它补上一条来自发言选项的依赖。 | 删除内置发言题，只保留订阅“收到消息”的普通题，配置可保存，判断请求数为零。保留发言题并选择沉默，该普通题也被跳过。 |
| 选项与会话 | `_assemble_result` 按 `action`、`target` 等用途解释答案，还单独识别名为 `length` 的题。工具目录目前仅有 `send_meme`。 | 普通题的“是”无法绑定调用会话模型。填写效果说明不会改变执行结果。 |
| 发送与后判断 | 入站收到“不发言”会提前退出，冷场有单独的发言条件。工具执行又检查一次 `should_speak()`。后判断取得最终正文后异步运行，目前仅写日志。 | 即使开放配置字段，独立工具仍会被运行时拦住。后判断选中的工具也没有执行入口。 |

以上两个触发案例用当前配置解析器和 `ask_decision` 实测。给自定义题绑定未注册的发言工具、把后继题接到内置沉默选项，两份配置都被严格校验拒绝。旧测试覆盖了默认发言分支的多种提问时机，遗漏了用户删除模板、从零搭建的路径。

## 触发和并发

- **事件触发一道题。** “收到消息”和“达到冷场时长”各自激活订阅它的全部题。题目直接订阅事件，就是入口，同一事件可以触发多道独立题。今后的事件须有实际产生它的回调。
- **定时触发。** `timer_elapsed` 只用于生成前判断，必须带 `interval_seconds`（15～2147483647 的整数）或 `daily_time`（`HH:MM`），两者互斥，每题至多一个定时入口。后台复用 15 秒轮询，按已知会话独立计时，仅把本次到期题设为入口；每日时间使用 AstrBot 会话时区，缺省使用服务器时区。新消息不重置定时器，忙碌时延后执行，不补跑错过次数，重启不恢复。发言共用主动额度与冷却，不依赖冷场开关。定时订阅存在期间，会话不会因一天无活动被清理。
- **上游选项触发一道题。** 依赖发言的题直接保存“问题 A 选了选项 B”。“否”和“保持沉默”也可以接后继。一个选项可以触发多题，一题已有的多个来源按任一命中处理，同一轮只采用一次。
- **提问时机存在依赖边上。** 子题可以选“随上游同批提问”或“上游命中后再问”。同批只提前向判断模型要答案。只有满足依赖的答案才能传给会话模型、触发下游和执行工具。需要上游返回的具体数据来构造题干或候选时，应等待数据。前后判断也不能跨过正文生成一起问。
- **动作可以为空。** 答案照常记录，显式依赖该选项的子题照常运行。某道题选了沉默，仅表示它的这个选项没有请求正文。其他订阅同一事件的题各自结算。

## 把现有能力放进可选的动作目录

选项可绑定零到多个动作。判断题支持固定选项、最近用户消息候选和图库候选。选择候选得到本轮快照里的消息或表情，可作为动作参数。一道普通选择题就能选消息，无需先赋予它“控制目标”的专属用途。

| 选项可绑定的动作 | 输入 | 运行时作用 |
| --- | --- | --- |
| 调用会话模型发言 | 当前会话和触发事件 | 登记本轮需要一份正文。等生成前的有效答案结算，汇总材料，再启动一次生成。重复命中合并，保留各自来源。 |
| 将内容交给会话模型 | 固定提示、本题答案或明确引用的有效答案 | 将篇幅、语气、普通答案等作为本轮临时材料。消息候选取发送人、发送时间和完整原文，判断时可以展示摘要。 |
| 引用指定消息 | 选中的消息 | 把该消息 ID 交给平台发送层，沿用无引用、仅首段、全段三种策略。用户可以只把原文交给模型，也可以同时绑定引用。 |
| 发送表情包 | 选中的表情 | 复用现有发送函数。独立发送在本轮判断被接纳后执行，随正文配图则等正文确认发送。旧配图配置迁移为后者。 |

目录为每个动作声明参数类型、允许阶段和必要条件。参数可以引用当前动态选项，或指向具体题目的有效答案。没有候选、未命中或缺少参数时只跳过依赖它的动作。选项效果说明、预览和实际执行从同一份绑定读取。判断模型负责选项，插件负责兑现选项。会话模型自身可用的 AstrBot 工具仍由官方 Agent 在生成期间调度，插件的“调用会话模型”只由判断流程调用，以免递归。

下面是一道普通题的实际配置。把动作从“是”移到“否”，同一题就会在答“否”时触发生成。后继题单独保存自己的触发来源，例如 `{"question":"join_chat","option":"true","ask_with_parent":true}`。

```json
{
  "id": "join_chat",
  "type": "boolean",
  "instructions": "现在加入讨论合适吗？",
  "triggers": [{"event": "message_received"}],
  "actions": {
    "true": [{"tool": "request_reply"}],
    "false": []
  }
}
```

## 编辑器对接

- 读取 `GET decision-config?version=7`。返回 `events`、`candidate_sources`、`actions`、`default_questions` 和当前的 `decision_questions`。旧配置在此投影为完整的版本 5 配置，读取不会写盘。目录中的 `stages`、`parameters`、`source` 和 `when` 说明动作可用阶段、参数和候选类型。
- 保存 `POST decision-config`，提交 `{"version":7,"decision_questions":[...]}`。后端保存的配置为 `{"version":5,"questions":[...]}`。旧编辑器继续读写旧图。首次保存新版图后，旧编辑器的写请求会被拒绝，避免丢失动作。
- 预览 `POST decision-preview`，提交 `version: 7`、`scene`、`decision_questions` 和示例 `answers`。返回各批次的 `asked/used/discarded`、有效答案、`reply`、`reply_sources`、`context`、`quote` 和 `tools`。预览仅使用样例消息和图库。
- 主动场景预览可带 `trigger_event: "timer_elapsed"`，假定全部定时入口同时到期；省略时保留冷场预览。定时轮次的决策日志带同名 `trigger_event` 字段，正文生成使用定时提示，不假定会话已经冷场。
- `candidate_source` 可取 `options`、`recent_messages`、`memes`。动态候选通过选项 `*` 绑定动作。动作的 `from` 填具体题目 ID，省略时读取本题答案。`add_context` 还可用 `text` 传入固定内容，或用 `label` 为传给会话模型的字段命名。`quote_message` 需要消息候选。`send_meme` 需要图库候选，默认 `when: "on_match"`，随正文配图填 `when: "after_send"`。
- `scenes` 可限定群聊、私聊和冷场场景。`requires_candidates` 可让普通布尔题只在存在特定类型的候选时提问。`private_default` 指定私聊收到消息时的固定选项。`triggers: []` 的题保留为待连接。删除父题时也可一并移除子题对应的触发条件，保留其余来源。
- 多处请求发言时生成一次，`reply_sources` 保留各个来源。一个消息段支持一个引用目标；多个有效引用绑定同时命中时采用配置顺序中最后一个。相同表情、相同发送时机的调用在本轮合并一次。

## 一次群消息怎样走完

| 问题，由管理员任意命名 | 唯一需要填写的触发来源 | 选项的实际结果 |
| --- | --- | --- |
| A「现在要接话吗」 | 收到消息 | “接话”绑定“调用会话模型发言”，“略过”留空。 |
| B「要针对某条消息吗」 | A 选“接话” | “要”触发 C，“随聊”照常生成。B 本身无需动作。 |
| C「针对哪条」 | B 选“要” | 选项取最近用户消息，提供发送人、绝对发送时间和距今时长。选中具体消息后，同时绑定“将这条消息交给会话模型”和“引用这条消息”。 |
| D「有人在提问吗」 | 收到消息 | 独立记录答案。即使 A 选择略过或已被删除，D 也能工作。 |
| E「这段回答适合配图吗」 | 本轮会话正文生成完成 | 读完整正文。选“适合”后可继续选图，绑定“正文确认发送后发送表情包”。 |

默认让 B 随 A、C 随 B 同批提问。A、B、C、D 都用模型且候选齐备时，四题可以共用一次判断请求。A 略过时丢弃 B、C 的预答，保留 D。A 接话而 B 选随聊时，调用一次会话模型并丢弃 C 的预答。另建一道“现在要主动开口吗”，只订阅冷场事件，“开口”绑定同一个发言动作，即构成独立冷场流程。

入站发言动作复用 AstrBot 官方会话交接。已由官方唤醒的单条消息沿用其默认请求，合并消息或群聊主动插话沿用显式构造请求的路径。冷场由插件使用当前会话的模型、人格和历史生成。插件接管范围内的事件，最终清单有发言动作就启动一条正文流程，只有独立工具就只执行工具，同时抑制宿主的默认回复。插件关闭、命令处理等原本由宿主处理的事件保留宿主所有权。合并窗口内的重新判断可以替换待执行动作，只有最终采纳的一轮产生外部效果。

后判断的起点是本轮最终正文可用。正文生成完成和平台发送确认是两个事实。记录类后判断可异步运行，依赖发送确认的工具要等到判断结果和发送结果都已到达，任一方先到都可以。流式以完整正文结算一次，中间工具调用、错误提示和半截输出不触发配图。后判断只列出当前阶段能兑现的动作，防止给已完成的正文追加提示或再次启动同轮生成。

## 实施顺序和验收

1. **先建立空配置用例。** 从保存配置、重新加载到执行都走正式入口。验证只建 D、只建 A、A+D 同时运行、改名、删 A 后 D 仍运行。删除父题后保留子题为待连接状态，不能自动把它提升成入口。模型调用次数和实际工具调用次数分别断言。
2. **修正事件分发和流程校验。** 在 `config_util.py`、`decision_engine.py` 实现两种显式触发，继续检查环路、失效引用与阶段。检查 `main.py` 中位于分发之前的插话开关、冷却、主动次数限制。属于发言额度的条件放到发言动作，消息过滤、冷场时长和每次冷场只触发一次保留在事件来源。无订阅可直接跳过评估。
3. **接通动作和两条生成路径。** 在 `models.py`、`decision_tools.py` 表达选项动作及参数，在判断结算后生成本轮调用清单。改造 `main.py`、`reply_generator.py` 的接纳、发送和后判断回调。普通答案由绑定决定是否交给会话模型，篇幅题改名后仍生效。测试不发正文时执行独立工具、两项同时要求发言仅生成一次、判断重算和回调重入不重复发送、试运行无外部效果。
4. **迁移并交付前端所需的配置契约。** 新格式提供事件、候选来源、动作参数、执行时机和预览结果。将 v4 实际生效的隐式发言依赖写成明确的上游选项，同时保留原并发设置。找不到旧发言入口的孤立题保留为待连接并给出迁移说明。旧的会话提示、普通答案注入、私聊默认固定回复、权重、阈值和引用策略均要有对应配置可重建。读回旧图与迁移图比较模型请求、有效答案、正文和工具次数。默认配置也从这份公开契约生成。UI 交接以这份数据及行为为准。

发布验收以删除全部默认题后的重建结果为准。重点比较群聊收到消息、冷场、独立判断、并发预答被丢弃、无候选、后判断先于或晚于发送确认六类场景。引用另核对普通分段和流式在三个引用档位的实际出站消息。
