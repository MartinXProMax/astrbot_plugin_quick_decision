# 对接通用 TTS

[通用 TTS](https://github.com/CyrilPeng/astrbot_plugin_universal_tts)（`astrbot_plugin_universal_tts`，按 1.4.5 对接）在 AstrBot 发送前把模型回复换成语音。快速决策用它的引擎合成语音，但正文发语音还是文字由每轮判断决定，不再按它的触发概率抽签：

- 默认问题 `use_voice` 在正文生成前判断这轮发语音还是文字，`voice_tone` 在正文生成后按实际回复判断朗读语气；
- 冷场和定时发言也能转成语音；
- 回复变成语音后，照常记录回复、补发表情。

适配器在 [`tts_adapter.py`](../tts_adapter.py)，状态和开关在 WebUI「外部插件」页。

## 推荐设置

| 位置 | 设置 | 原因 |
| --- | --- | --- |
| 通用 TTS | 「触发概率」设为 0 | 是否转语音交给判断。概率不为 0 时，判断为只发文字的回复会先被它合成一次，再改回文字 |
| AstrBot 配置 | 打开「启用 TTS」 | 通用 TTS 以这个全局开关和会话的 TTS 开关为准，没打开就不合成 |
| AstrBot 配置 | 「TTS 提供商」留空 | 选了提供商时，只发文字的回复要按普通消息发送，否则会被内置 TTS 转成语音，这样 AstrBot 分段回复就不生效 |
| AstrBot 配置 | 关闭流式输出 | 流式结果不经过发送前处理，不会转语音 |
| 通用 TTS | 保持「发送失败时回退为文字」开启 | 语音发不出去时改发原文；快速决策的主动发言也按这一项处理 |
| 快速决策「外部插件」 | 「冷场和定时发言也转语音」 | 默认开启。关掉后主动发言只发文字，也不再问是否用语音 |
| 判断配置 | 有定时发言的题时，让 `use_voice` 也从它的发言选项触发 | 默认的 `use_voice` 只接在 `action` 和 `idle_action` 之后，定时回合问不到它，定时消息会按通用 TTS 的触发概率决定（概率为 0 就只发文字） |

`/decision status` 的「语音」一行和「外部插件」页会显示当前引擎，并指出缺了哪项设置。「外部插件」页的「避免两个插件重复执行」会按当前配置逐项检查上表中的设置，已做到的打钩；通用 TTS 没加载时，它自己的两项无法检查，显示为虚线框。

## 默认问题：是否用语音

全新安装和「恢复默认问题」都带这两道题。`use_voice` 接在发言题 `action`（收到消息）和 `idle_action`（冷场）之后，与发言题同一批提问；`voice_tone` 是正文生成后的题，在 `use_voice` 选是时，拿实际生成的回复去判断语气：

| 题 | 选项 | 动作 |
| --- | --- | --- |
| `use_voice`（是否题） | 是 | 「正文转成语音」（`voice_reply`），并提示会话模型写口语化、适合朗读的句子 |
| | 否 | 「正文只发文字」（`text_reply`） |
| `voice_tone`（选择题，正文生成后，`use_voice` 选是时提问） | plain / happy / gentle / playful / sad / angry | 「设定语音语气」（`voice_tone`） |

用到语音动作的题只在能转语音时提问。以下情况会直接跳过，不多花一次判断：

- 没装通用 TTS，或者装了但没对上；
- 「外部插件」里停用了它；
- AstrBot「启用 TTS」未打开，或用 `/tts_off` 暂停了；
- 本会话用 `/tts_bind 0` 禁了音，或 AstrBot 关了本会话的 TTS；
- 被动回合并且 AstrBot 开着流式输出（流式回复转不了语音；冷场、定时发言不走流式，不受影响）；
- 冷场、定时回合并且关了「冷场和定时发言也转语音」。

判断配置页的流程预览也按同样条件显示（预览没有具体会话，不检查会话禁音）。已有的判断配置不会自动改动，可以在「外部插件」页一键加入这两道题。早先加入的正文生成前的 `voice_tone` 仍然可用，只是按语境而不是按回复内容判断；想改成按回复判断，可以删掉它再从「外部插件」页重新加入。

语气要等正文生成后再判断，所以发语音的回复会多等一次判断：语气判断结束后才合成语音，最多等 15 秒，超时就用引擎默认的语气。只发文字的回复不等。

## 判断结果怎样落实

被动回复包括群聊插话、@、私聊和合并后的入站消息，它们走官方流水线。AstrBot 依次执行 `on_decorating_result` 钩子：

1. 快速决策（`priority=10`）先处理：取消不发言轮次的正文，去掉群聊的官方引用，记下模型原文。判断为发语音时，先等正文生成后的语气判断（模型回复一到就已开始），再按触发概率 100% 执行通用 TTS 的 `tts_hook`，并带上本轮语气。概率之外的规则照常生效，包括字数上限、跳过规则、`/tts_off`、会话禁音和会话绑定的引擎。
2. 通用 TTS（`priority=0`）照常运行：
   - 文字已换成语音时，它没有文字可转；
   - 判断为只发文字时，它可能按自己的概率转出语音，也可能跳过，并把结果改标为普通消息。
3. 快速决策（`priority=-10`）收尾：
   - 判断为只发文字、链上却出现了它转的语音：换回原来的文字组件；
   - 结果被改标为普通消息：改回模型结果，让 AstrBot 分段回复照常生效。如果内置 TTS 选了提供商、链上还有文字，就保持普通消息，免得内置 TTS 再转语音。
4. RespondStage 调用 `event.send`。aiocqhttp 把语音 `Record` 转成 `base64://` 发进群里。

没有给出发送方式的回合，仍由通用 TTS 自己决定。这包括判断配置里没有 `use_voice`、这题没答出结果，以及停用了适配器的情况。

主动发言（冷场、定时）由快速决策直接调用 `context.send_message`，不经过上述钩子：

- 判断为只发文字：不调用通用 TTS；
- 判断为发语音：等正文生成后的语气判断，再用一个只带会话标识和正文的事件，按触发概率 100% 调用它的钩子，取回语音；
- 没有判断：按它的概率。

转成语音时，整段正文作为一条语音发出，不分段、不带引用；没转时按原来的分段发文字。

QQ 语音不能带引用气泡，所以「回复哪一条」选出的目标消息只交给会话模型参考。语音之后的表情仍作为独立一条发送。

## 会不会语音、文字各发一遍

不会。通用 TTS 用语音替换文字，快速决策每轮也只发一次正文。只有以下情况发文字：

- 判断为只发文字；
- 通用 TTS 按规则跳过，例如超出字数上限、命中跳过规则或已 `/tts_off`；
- 语音发送抛错，并且开着「发送失败时回退为文字」，这时改发原文。

可能出现两份的只有 AstrBot 内置 TTS 的「同时输出语音和文字」（`dual_output`）。它只在内置 TTS 选了提供商、并接手了某条回复时才起作用。按上表把 TTS 提供商留空即可避免，「外部插件」页检测到这种组合时会提示。

快速决策这边：

- 语音送达后，决策日志记为已回复并标注「（语音）」，`voice_mode`、`voice_tone` 也记在日志里。日志和会话上下文用的都是模型原文。
- 结果被改标为普通消息时，快速决策仍按本轮的模型结果处理引用和送达回执。
- 语音发送失败后通用 TTS 改发的原文，按本轮正文计入，不会被当成别的插件的消息，也不会导致表情不发。

## 朗读语气

通用 TTS 的语气写在引擎配置里，没有提供给其他插件的接口。`voice_tone` 在正文生成后看着实际回复判断，各选项把语气交给「设定语音语气」动作，语气词可以在判断配置里改。「设定语音语气」也可以用在正文生成前的题上，这时语气只能按语境猜：

| 选项 | 判断标准 | 交给通用 TTS 的语气 |
| --- | --- | --- |
| `plain` | 平静自然 | 不改，沿用引擎配置 |
| `happy` | 开心、轻快 | 开心 |
| `gentle` | 温柔、安抚 | 温柔 |
| `playful` | 俏皮、撒娇 | 俏皮 |
| `sad` | 低落、委屈 | 难过 |
| `angry` | 生气、不满 | 生气 |

合成时，快速决策取本会话该用的引擎（绑定的或全局的），复制一份并在副本上叠加语气，原引擎不变。副本与原引擎共用同一个 HTTP 客户端。叠加方式因引擎而异：

- **MiMo V2.5-TTS**：语气追加在原有风格词之后，例如原风格「温柔，慵懒」加上「开心」，实际发送 `(温柔 慵懒 开心)`。
- **Azure**：`express-as` 只能有一个 style，本轮语气替换原 style。默认的中文语气会换成 Azure 风格名：开心 → `cheerful`、温柔 → `gentle`、俏皮 → `affectionate`、难过 → `sad`、生气 → `angry`（另有平静、兴奋、友好、严肃等常见说法）；也可以直接填 Azure 风格名。换不成英文名的语气不替换，保留引擎原有的 style。
- **MiMo VoiceClone**：在 `style_prompt` 末尾补一句「用「开心」的语气朗读。」
- **其他引擎**（OpenAI 兼容、火山、阿里、ElevenLabs、自定义 HTTP）：没有风格参数，忽略语气。

## 依赖与限制

通用 TTS 没有公开接口，适配器依赖它 1.4.x 的内部名称：

- 插件名 `astrbot_plugin_universal_tts`；
- 方法 `tts_hook`、`_get_engine_for_session`；
- 配置项 `tts_probability`、`fallback_to_text_on_send_error`；
- 引擎属性 `style`、`style_prompt`、`role`、`_get_client`。

对不上时有三种情况：

- 找不到插件或钩子：「外部插件」页显示不兼容，语音题跳过，主动发言只发文字；
- 引擎没有风格属性：忽略语气；
- 合成出错：被动回复交还给通用 TTS 默认处理，主动发言改发文字。

触发概率不为 0 时，判断为只发文字的回复会被白白合成一次。这次合成会计入它的统计和最近文本缓存，临时文件按它的保留时间清理。

AstrBot 开了「内容安全检查回复」时，通用 TTS 跳过回复时不改结果类型。

如果通用 TTS 以后支持按消息传入「是否转语音」和风格（例如读取事件上的某个 extra），应改为调用该接口，不再借用它的钩子和复制引擎。
