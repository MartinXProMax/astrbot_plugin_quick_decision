# 对接通用 TTS

[通用 TTS](https://github.com/CyrilPeng/astrbot_plugin_universal_tts)（`astrbot_plugin_universal_tts`，按 1.4.5 对接）在 AstrBot 发送前把模型回复换成语音。回复要不要转、用哪个引擎、什么音色，都还是它自己决定。快速决策补了三件事：

- 冷场和定时发言也能转成语音；
- 按判断结果切换每一轮的朗读语气；
- 回复变成语音后，照常记录回复、补发表情。

适配器在 [`tts_adapter.py`](../tts_adapter.py)，状态和开关在 WebUI「外部插件」页。

## 推荐设置

| 位置 | 设置 | 原因 |
| --- | --- | --- |
| AstrBot 配置 | 打开「启用 TTS」 | 通用 TTS 以这个全局开关和会话的 TTS 开关为准，没打开就不合成 |
| AstrBot 配置 | 「TTS 提供商」留空 | 选了提供商时，通用 TTS 合成失败的回复会由内置 TTS 再转一次 |
| AstrBot 配置 | 关闭流式输出 | 流式结果不经过发送前处理，通用 TTS 和内置 TTS 都不会转语音 |
| 通用 TTS | 保持「发送失败时回退为文字」开启 | 语音发不出去时改发原文；快速决策的主动发言也按这一项处理 |
| 快速决策「外部插件」 | 「冷场和定时发言也转语音」 | 默认开启。关掉后主动发言只发文字 |

`/decision status` 的「语音」一行和「外部插件」页会显示当前引擎，并指出缺了哪项设置。

## 在 QQ 群里怎样发出语音

被动回复包括群聊插话、@、私聊和合并后的入站消息，它们走官方流水线。AstrBot 依次执行 `on_decorating_result` 钩子：

1. 快速决策（`priority=10`）先处理：取消不发言轮次的正文，去掉群聊的官方引用，记下模型原文。判断给了语气时，还会代通用 TTS 合成一次（见下文）。
2. 通用 TTS（`priority=0`）把整条回复的全部文字合成为一条语音，替换掉第一段文字，删掉其余文字。图片等其他组件保持原顺序。
3. RespondStage 调用 `event.send`。aiocqhttp 把 `Record` 转成 `base64://` 发进群里。

主动发言（冷场、定时）由快速决策直接调用 `context.send_message`，不经过上述钩子，原本只能发文字。现在快速决策用一个只带会话标识和正文的事件调用通用 TTS 的 `tts_hook`。它的全部规则照常生效，包括插件总开关、`/tts_off`、AstrBot 和会话的 TTS 开关、触发概率、字数上限、跳过规则和 `/tts_bind`。转成语音时，整段正文作为一条语音发出，不分段，不带引用。没转时按原来的分段发文字。

QQ 语音不能带引用气泡。所以「回复哪一条」选出的目标消息只交给会话模型参考，不会出现在语音上。语音之后的表情仍作为独立一条发送。

## 会不会语音、文字各发一遍

通用 TTS 不会。它用语音替换文字，没有同时发两份的选项。只有两种情况会发文字：

- 它跳过了这条回复。原因可能是概率没抽中、超出字数上限、命中跳过规则或已 `/tts_off`，这时只发文字。
- 语音发送抛错，并且开着「发送失败时回退为文字」，这时改发原文。

可能出现两份的只有 AstrBot 内置 TTS 的「同时输出语音和文字」（`dual_output`）。它只在内置 TTS 选了提供商、并且接手了通用 TTS 没转的回复时才起作用。按上表把 TTS 提供商留空即可避免。「外部插件」页检测到这种组合时会提示。

快速决策这边，每轮只发一次正文：

- 语音送达后，决策日志记为已回复，并标注「（语音）」。日志里的回复内容和会话上下文用的都是模型原文。
- 通用 TTS 跳过时会把结果标成普通消息。快速决策仍按本轮的模型结果处理引用和送达回执。
- 语音发送失败后，通用 TTS 改发原文。这份原文按本轮正文计入，不会被当成别的插件的消息，也不会导致表情不发。

## 朗读语气

通用 TTS 的语气写在引擎配置里，每句都一样。它也没有提供给其他插件的接口。快速决策新增了「设定语音语气」动作（`voice_tone`）。「外部插件」页提供一道可选题 `voice_tone`，可以一键加入判断配置。它不在「恢复默认问题」里，没装通用 TTS 的用户不会多一次判断。

| 选项 | 判断标准 | 交给通用 TTS 的语气 |
| --- | --- | --- |
| `plain` | 平静自然 | 不改，沿用引擎配置 |
| `happy` | 开心、轻快 | 开心 |
| `gentle` | 温柔、安抚 | 温柔 |
| `playful` | 俏皮、撒娇 | 俏皮 |
| `sad` | 低落、委屈 | 难过 |
| `angry` | 生气、不满 | 生气 |

每个选项除了设定语气，还用「将内容交给会话模型」把「语气：开心」之类交给会话模型，让文字内容和朗读语气一致。语气词可以在判断配置里改。

合成时，快速决策取本会话该用的引擎（绑定的或全局的）。它复制一份引擎，在副本上叠加语气，原引擎不变。副本与原引擎共用同一个 HTTP 客户端。叠加方式因引擎而异：

- **MiMo V2.5-TTS**：语气追加在原有风格词之后，例如原风格「温柔，慵懒」加上「开心」，实际发送 `(温柔 慵懒 开心)`。
- **Azure**：`express-as` 只能有一个 style，本轮语气替换原 style。语气要填 Azure 的风格名，如 `cheerful`、`sad`。
- **MiMo VoiceClone**：在 `style_prompt` 末尾补一句「用「开心」的语气朗读。」
- **其他引擎**（OpenAI 兼容、火山、阿里、ElevenLabs、自定义 HTTP）：没有风格参数，忽略语气。

被动回复中，快速决策的钩子先用带语气的引擎跑一次通用 TTS 的 `tts_hook`：

- 转成功：通用 TTS 自己的钩子看不到文字，不会再合成；
- 它按规则跳过：会把结果标成普通消息，它自己的钩子也随之跳过；
- 合成失败：交给它自己的钩子，用默认语气重试一次。

例外是 AstrBot 开了「内容安全检查回复」。这时通用 TTS 不改结果类型，概率小于 100% 时它自己的钩子会再抽一次。

## 依赖与限制

通用 TTS 没有公开接口，适配器依赖它 1.4.x 的内部名称：

- 插件名 `astrbot_plugin_universal_tts`；
- 方法 `tts_hook`、`_get_engine_for_session`；
- 引擎属性 `style`、`style_prompt`、`role`、`_get_client`。

对不上时有三种情况：

- 找不到插件或钩子：「外部插件」页显示不兼容，主动发言只发文字；
- 引擎没有风格属性：忽略语气；
- 合成出错：被动回复交还给通用 TTS 默认处理，主动发言改发文字。

如果通用 TTS 以后支持按消息传入风格（例如读取事件上的某个 extra），应改为调用该接口，不再复制引擎。
